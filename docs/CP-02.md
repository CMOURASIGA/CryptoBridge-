# CP-02 | Mercado Bitcoin private read-only adapter (candidate)
Date 2026-11-05. No Supabase dependency.

## Verified provider contract
Source: https://api.mercadobitcoin.net/api/v4/docs

- OAuth2 client_credentials token: POST /api/v4/oauth2/token with grant_type=client_credentials, scope=global, client_id and client_secret (form-urlencoded).
- Bearer token for authenticated requests.
- GET /api/v4/accounts for account listing.
- GET /api/v4/accounts/{accountId}/balances (available, on_hold, total, symbol).
- GET /api/v4/accounts/{accountId}/orders for account order list.

**Critical limitation:** the documented OAuth scope is `global`. This is NOT proof that exchange-issued keys are read-only or restricted to that permission. Before any real credentials are used, verify API key permission controls and obtain explicit owner authorization. The client enforces GET requests only for allowlisted read paths. The authentication token POST is the only POST that is permitted.

## Current implementation
`MercadoBitcoinReadClient` includes schema checks, cache of access token within process memory, bounded timeouts, account ownership check, HTTP error redaction, GET route allowlist, and no trading-related methods. The client is **not exposed as a live MCP tool** in this release. There is no secure secrets vault or session-to-user mapping yet, so none of the private data tools is enabled.
